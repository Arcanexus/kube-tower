Versions, lifecycle and vulnerabilities
of all your clusters, at a glance.

kube-tower inventories every container image and every Helm chart of all your clusters, compares each version with the latest one published in its registry, tells you how far behind it is (patch, minor, major) and which vulnerabilities it carries, so you know what to update first.

Features

Every version, its lifecycle and its risks

What runs where, how far behind it is, and what it exposes: the version checks of watchtower, Renovate and version-checker plus Trivy, in one view.

Every image

Pods, Deployments, StatefulSets, DaemonSets and CronJobs, running or not, plus the images cached on the nodes.

Checked at the source

Each image is compared with the registry of its manifest: Docker Hub, ghcr.io, quay.io, ECR, Artifact Registry, ACR, Harbor, Artifactory, Nexus or any OCI registry.

Smart tag matching

1.25.3-alpine is only compared with x.y.z-alpine, semver with semver, dates with dates. Floating tags like latest are checked by digest.

Helm charts and subcharts

Charts deployed by ArgoCD Applications, from Helm repositories, OCI registries or git, with every dependency checked.

Vulnerabilities

CVEs read from Trivy Operator reports, or scanned with Trivy. Search a CVE ID to find every image it affects.

Security reports

Misconfigurations, exposed secrets, risky RBAC roles and CIS, NSA or Pod Security Standards compliance, with how to fix each finding.

All your clusters

Register clusters ArgoCD-style with a Secret, or reuse the cluster Secrets ArgoCD already has.

Private registries

Per registry credentials, IRSA and EKS Pod Identity, GKE and AKS Workload Identity, the clusters' pull secrets, private CAs.

Login, SSO and roles

A built-in admin account, local accounts, OpenID Connect or the Dex of the chart, readonly and admin roles from your groups.

Scales out

One small pod by default. For large inventories, UI, controller, worker and Trivy pods scaled apart with Valkey or Redis.

Observable

JSON API and Prometheus metrics, with a ready-made Grafana dashboard and alert examples.

Made for triage

A To do list sorted by urgency, filters kept in the URL, detail panels, per item rescans, live logs, dark theme and phones.

How it works

Install once, see every cluster

  1. Discover. kube-tower finds its own cluster and every cluster registered with a Secret, ArgoCD-style.
  2. Collect. With a read-only ServiceAccount, it lists workloads, node images and ArgoCD Applications.
  3. Check. It asks each registry for its published versions, once per repository, and reads or scans the vulnerabilities.
  4. Show. The result stays in memory and feeds the UI, the JSON API and /metrics, refreshed every 6 hours or on demand.

Get started

Running in two minutes

One Helm chart, one small pod. Open the UI and log in as admin.

# Install the chart
helm install kube-tower oci://ghcr.io/arcanexus/charts/kube-tower \
  --namespace kube-tower --create-namespace

# Open the UI on http://localhost:8080
kubectl -n kube-tower port-forward svc/kube-tower 8080:80

# Password of the admin account, generated at the first start
kubectl -n kube-tower get secret kube-tower-auth \
  -o jsonpath='{.data.admin\.password}' | base64 -d; echo
